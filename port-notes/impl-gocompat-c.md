# impl-gocompat-c: `dstore-gocompat` json, hex, base32, errno, path, os (layer L1)

Owner: gocompat-c. Files: `crates/gocompat/src/{json,hex,base32,errno,errno_tables,path,os}.rs`,
`tools/vectorgen/family_gocompat_io.go`, `tools/vectorgen/cmd/goerrno/`, `tools/vectorgen/docs/gocompat-c.md`,
`tests/golden_tests/gocompat_io.rs`.

## Additions beyond PORTING.md §4.1 (nothing changed)

1. **`JsonError::ValueType { value, go_type }`**
   - Text: `json: cannot unmarshal <value> into Go value of type <go_type>`.
   - When: Go's text for a top-level value that is not an object (`"x"`, `5`, `true`, `[]`), which has no
     struct context. §4.1's `JsonError::Type` only has the struct-field form.
2. **`unmarshal_object`'s `go_struct` argument.** Pass the package-qualified Go type name, e.g.
   `"worktree.Config"`:
   - field errors use the part after the last `.` (`Go struct field Config.ticket`, Go's `Type.Name()`);
   - `ValueType` uses the whole string (`Go value of type worktree.Config`, Go's `Type.String()`).

   A caller that passes `"Config"` still gets exact field errors, but top-level mismatches would read
   `Go value of type Config`.
   - **worktree owner:** pass `"worktree.Config"` for `.dstore/config`, and `"worktree.stateJSON"` for
     `.dstore/state`, whose Go struct is the unexported `stateJSON`.
3. **`errno::errno_string(code) -> String`**: `syscall.Errno.Error()`, the table text or `errno <n>`.
   - `io_error_text` and `rewrite_os_errors` use it for raw errnos Go's table lacks.
4. **`hex::latin1_is_print`** (`pub(crate)`): `strconv.IsPrint` for runes up to U+00FF. `json` uses it for
   scanner error quoting, so these modules do not wait for `quote`.
5. **`errno_tables.rs` shape.** One `ERRORS: &[(i32, &str)]` per `cfg(target_os, target_arch)`, generated by
   `go run ./cmd/goerrno`.
   - darwin/arm64 adds errno 106, and linux/arm64 adds 133, so a per-OS table would be wrong on one arch.
   - Other architectures fall back to the arm64 table (macOS) or the amd64 table (Linux).
   - Other OSes get an empty table.

## Behaviour notes for callers

- **json.**
  - A syntax error leaves every slot `None`, because Go's `checkValid` runs before decoding.
  - `null` leaves a slot `None`, so the caller keeps its default.
  - Field names must be ASCII (all dstore struct tags are). `foldName` is exact for runes folding to ASCII
    (U+212A, U+017F); other non-ASCII runes are compared as is.
- **hex.** `decode_string` reports an invalid byte before an odd length. Texts use `%#U`
  (`U+00C3 'Ã'`, `U+0001`).
- **base32.**
  - Decoding includes Go's padding branch, which a 0xFF input byte can reach
    (`AA\xff\xff\xff\xff\xff\xff` decodes, and bytes after the "padding" are ignored).
  - Error offsets count the `\r`/`\n`-stripped input.
- **errno.**
  - `io_error_text` gives `errno <n>` for an errno without Go text; a custom `io::Error` renders its message.
  - `rewrite_os_errors` replaces `<Rust strerror> (os error N)` only where the text before the suffix is
    Rust's own rendering of N.
- **path.** `rel` returns `None` where Go errors. A caller that needs the error builds
  `Rel: can't make <target> relative to <base>` from the original arguments; the golden test checks this
  formula against Go's bytes for every error case. Go 1.26 cleans the upward result of `Rel`, and so does
  the port.
- **os.**
  - Go's texts: `mkdir`/`remove`/`open`/`read`/`write`/`close`/`createtemp`/`RemoveAll`/`unlinkat`/
    `openfdat`/`readdirnames` ops, and `EINVAL` for a NUL byte in a path.
  - `getwd` failures are `io::Error`s whose message is Go's `stat .: …` or `getwd: …`, so `io_error_text`
    renders them exactly.
  - `remove_all` ports `removeall_at.go`:
    - unlinkat, and openat with O_NOFOLLOW|O_DIRECTORY;
    - batches of 1024 names, skipping zero-inode entries as Go does;
    - Go's path prefixing of nested errors;
    - inner ops `readdir` (darwin) / `readdirent` (linux). An fdopendir failure reads `fdopendir` on darwin,
      as Go's `poll.FD.OpenDir` does, and `readdirent` on linux.
  - `create_temp` names are `prefix + decimal u32 + suffix`, O_EXCL 0600, 10000 tries, then
    `createtemp <dir>/<prefix>*<suffix>: file already exists`.
  - `current_username`:
    - darwin: `getpwuid_r` with Go's buffer sizing (`sysconf` -1 → 1024, other sizes outside (0, 1 MiB] →
      1 MiB), buffer doubling and texts.
    - linux (cgo-less, as the dstore Dockerfile builds): `/etc/passwd` lines trimmed with `bytes.TrimSpace`
      (through `strings::trim_space`), then `$USER` if `$USER` and `$HOME` are set, else
      `user: Current requires cgo or $USER, $HOME set in environment`.
    - A Linux Go binary built with cgo uses `getpwuid_r` (NSS). The port follows the cgo-less build.

## Not ported, or simplified

- `getwd` does not port Go's slow fallback (walking `..` when getcwd fails with ENAMETOOLONG or ERANGE, e.g.
  a working directory longer than Go's `PathMax`). Rust's `current_dir` grows its buffer instead.
- `os::write_file`/`read_file` use std's EINTR handling (std retries `open`; `mkdir`/`unlink`/`rmdir` are not
  retried on EINTR, which Go does).
- `current_username` on linux reads `/etc/passwd` whole; Go reads line by line and stops at the first match,
  so a read error after the matching line would give Go a name where the port falls back to `$USER`.

- the Rust port was compared line by line with the go1.26.5 sources: `encoding/json` scanner.go,
  decode.go, encode.go and fold.go; `encoding/hex`; `encoding/base32`; `internal/filepathlite`,
  `path/filepath` and `path`; `os` getwd.go, path.go, file_unix.go, removeall_at.go, root_unix.go,
  tempfile.go, file.go, dir_darwin.go and dir_unix.go; `os/user` lookup_stubs.go, lookup_unix.go,
  cgo_lookup_unix.go and cgo_lookup_syscall.go;
- the Go test tables were checked against the unit tests;
- the family was regenerated in the real module and the vectors checked against the VECTORS.md conventions.

### Confirmed correct (no change)

- **json:**
  - The scanner states and every error text: quoteChar, `eof`'s space step, `after top-level value` reported
    at eof, `exceeded max depth`.
  - Decoding: exact then folded key match, first folded field wins, `unquoteBytes` with surrogates and
    per-byte U+FFFD, `null` ignored, and the first-error rule.
  - `addErrorContext` uses `Struct.Name()`, while top-level errors use `Type.String()`.
  - `appendString` escaping (`\u00XX` lowercase, 0x7f raw, U+2028/U+2029, per-byte `�`).
- **hex:** Decode order and `%#U` texts.
- **base32:** the decode loop, including the 0xFF padding branch and its offsets, and the reverse-order
  remainder encoding.
- **path:** Clean, Join, Dir, path.Base, Abs, and Rel (with its final Clean).
- **os:**
  - `Getwd`'s $PWD rule and error texts; MkdirAll's parent scan; Remove's error selection.
  - `removeAllFrom`: EISDIR/EPERM/EACCES, ENOTDIR → the unlinkat error, errSymlink → openfdat with uErr,
    ENOTSUP → ENOTDIR, recurseErr overwritten by an openfdat failure, the 1024 batches, and path prefixing.
  - splitPath; CreateTemp (TempDir, prefixAndSuffix, joinPath, IsExist = EEXIST|ENOTEMPTY, texts).
  - WriteFile/ReadFile op names; darwin getpwuid_r error selection; `matchUserIndexValue` and Atoi.
- **Tests:**
  - The unit tests cover filepath cleantests/nonwincleantests, jointests/nonwinjointests, basetests,
    dirtests/nonwindirtests and reltests.
  - They also cover hex encDecTests and errTests, the base32 pairs (unpadded), and json TestUnmarshalSyntax
    and TestIndentErrors.
  - Go's `TestDecodeCorrupt` inputs are in the vectors, decoded without padding.
- **Generated files:**
  - `errno_tables.rs` regenerates byte-identical.
  - Nothing is `#[ignore]`d or skipped, and missing vector files fail through `load_json`.

### Found and fixed

1. **`/etc/passwd` trimming (linux `current_username`).** The port trimmed with `trim_ascii`, which misses
   `\v` and Unicode White_Space, where Go's `bytes.TrimSpace` strips them.
   - Fix: it now uses `strings::trim_space`, which has the same semantics.
   - Unit test added with `\v`, U+00A0, U+2003 and U+0085.
   - The earlier "ASCII whitespace" simplification is gone.
2. **darwin `getpwuid_r` initial buffer size.** Every negative `sysconf` result gave 1024; Go uses 1024 only
   for -1 and `maxBufferSize` for any other size outside (0, 1 MiB]. Fixed.
3. **`remove_all` fdopendir failure op.** It rendered `readdir`, while Go on darwin reports `fdopendir`
   (`poll.FD.OpenDir`). Now `fdopendir` on darwin; linux keeps `readdirent` (Go has no fdopendir step there).
4. **Zero-inode directory entries.** `readdirnames` returned them; Go's darwin and linux readdir skip
   `d_ino == 0`. Now skipped.
5. **VECTORS.md convention in `gocompat/path.json`.** 82 of the 171 `rel` error texts echoed `\xff` inputs and
   were written lossily (U+FFFD) into a JSON string.
   - Fix: the field is now `error_hex`.
   - The golden test also checks that `Rel: can't make <target> relative to <base>` built from the inputs
     equals Go's bytes. That text is what the port tells callers to build.
6. **codec-wire-ticket §5 G8 base32 grid** was only partly covered, and no other family owns it. Added to
   `gocompat/base32.json` for both alphabets:
   - `A`, `a`, `y`, `Y` × 0..17;
   - `=` at every position of `AAAAAAAA`, `MZXW6YTB`, `yyyyyyyy` and `ybndrfg8`;
   - mixed `\r`/`\n` inputs.

   Decode cases went from 782 to 908, and the port passes all of them.
7. **Unit tests added:** json `TestValid` (scanner texts for `foo`, `}{`, `{]`), and `filepath.Abs` of
   relative paths and `""`.

Docs (`tools/vectorgen/docs/gocompat-c.md`) were updated for items 5 and 6.
